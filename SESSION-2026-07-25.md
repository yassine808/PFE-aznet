Everything done in this session, why it was done, and what still needs your hands.

## 1. The bug you reported

**Symptom:** if the Google Sheets write failed, the technician never received their summary.

**Cause:** `n8n/reception-unified.json` wired the pipeline as
`Process output → Append Sheet row → TG or WA? (reply)`. n8n halts a branch when a node throws, so **Google's uptime was a hard dependency of the product's core promise**. A Sheets 500 meant the voice note was transcribed, extracted, paid for in free-tier quota — and then silently dropped.

**Fix — reply first, Sheet second:**

```
Process output → TG or WA? (reply) → TG/WA reply summary → Append Sheet row
                                                             ├─[ok]  → Log sheet OK
                                                             └─[err] → Queue failed write → Log sheet failed
```

The Sheet write is now a *recoverable side effect*, not a blocking dependency. On failure the report parks in a `failed_writes` table and a cron drains it — nothing is lost, and the technician always gets their reply.

## 2. Logs in the dashboard (Logs n8n panel)

### Store: PostgreSQL, not the Sheet

New `postgres` service in `docker-compose.yml` (`postgres:16-alpine`, volume `pg_data`, healthcheck).

The reasoning that decided this: **the single most important thing to log is "the Sheet write failed"** — and a Sheets-backed log goes blind during exactly the outage it exists to record. Postgres is an independent failure domain.

### `api/app/logs.py` (new)

Three tables:

| table | purpose |
|---|---|
| `pipeline_logs` | one row per stage, with `correlation_id`, `channel`, `technicien`, `level`, `duration_ms`, `payload` JSONB |
| `processed_messages` | WhatsApp idempotency (atomic `ON CONFLICT DO NOTHING` claim) |
| `failed_writes` | Sheet retry queue |

Connection handling uses a `ThreadedConnectionPool` behind a `_cursor()` context manager that commits/rolls back and returns the connection to the pool, converting every failure into one `LogStoreError` type.

### New endpoints in `api/app/main.py`

- `POST /logs`, `GET /logs` (filters: level, channel, stage, correlation_id, search), `DELETE /logs?days=30`
- `POST /logs/claim` — idempotency gate, returns `{"fresh": bool}`
- `POST /sheet-queue`, `GET /sheet-queue`, `PATCH /sheet-queue/{id}`
- `lifespan` handler creates the schema at startup; if `DATABASE_URL` is unset the API prints `[logs] DISABLED — …` and keeps serving. **Observability being down never stops the pipeline.**

The API also logs *its own* errors (`transcription failed`, `extraction failed`, bad input) with the same `correlation_id` n8n mints, so two separate processes join into one timeline.

### Dashboard panel

`web/src/components/logs-panel.tsx` — 4 counter tiles (events / errors / warnings / pending writes, last 24 h), a live-tail table polling every 5 s with a pause toggle, filters for level/channel/stage, debounced search, and click-to-expand raw JSON payload. Reachable from the new **Logs n8n** sidebar entry under Administration.

All copy added to `fr/en/ar` (141 keys each, in sync).

## 3. Workflow improvements

| Improvement | What it does |
|---|---|
| **Global error workflow** | `n8n/error-workflow.json` rewritten to POST `stage: workflow_error` to `/logs` instead of appending to a Sheet tab (an error handler that reports through Google cannot report Google failing) |
| **WhatsApp idempotency** | Was in-memory `$getWorkflowStaticData` — wiped on every n8n restart and invisible. Now a durable Postgres claim. Meta retries webhooks that don't get a fast 200, so this prevents duplicate Sheet rows, duplicate replies and duplicate Groq/Gemini quota burn |
| **Retries + timeouts** | `POST /process` (audio + text): 3 tries, 2 s backoff, 120 s timeout. Same retry policy on media download and `getUpdates` |
| **Sheet retry queue** | `n8n/maintenance-cron.json` (new): every 5 min drains `failed_writes` back into the Sheet; daily 03:00 prunes logs older than 30 days |
| **Per-stage logging** | 7 log nodes: received, denied, duplicate, replied, sheet OK, sheet failed, process failed |
| **Correlation ids** | New `Correlate` node mints one id per message, threaded through `/process` and every log row |

## 5. Review pass — bugs found and fixed

Three reviewers were fanned out over the backend, the n8n graph, and the frontend. They found real bugs, including ones introduced by this session's own changes.

### Backend (verdict was **block**)

1. **CRITICAL — connection leak.** psycopg2's `with conn:` commits the transaction but does **not** close the connection. With a connect-per-call design and several log writes per voice note, Postgres's 100-connection limit would be exhausted within minutes. → Replaced with a pooled `_cursor()` context manager.
2. **HIGH — `write_safe` under-caught.** It only caught `LogStoreError`, but mid-query psycopg2 errors (dropped connection, deadlock, statement timeout) propagate as `psycopg2.Error` — which would have turned a *successful* voice-note submission into a 500. → Now catches broadly, by design and documented.
3. **HIGH — endpoints leaked raw 500s** on mid-query failures. → `_cursor()` now converts every failure to `LogStoreError`, so all endpoints return a clean 502.
4. **MEDIUM — blocking I/O in an async handler.** `async def process()` called synchronous psycopg2 directly, stalling the event loop for every concurrent request. → All log writes go through `run_in_threadpool`.

### n8n (verdict was **do not deploy**)

5. **SEV-0 — log nodes were inline and severed the data path.** An `httpRequest` node outputs `{"ok":true,"id":N}`, which *replaced the message payload* for everything downstream: `correlation_id` became `"undefined-…"`, every message claimed the same id (so the second message ever received would be dropped as a duplicate forever), and `Authorized?` saw `undefined` → every technician treated as unauthorized. Nothing would have reached `/process`. → All 7 log nodes are now **leaves**, fanned out in parallel.
6. **SEV-0 — `Append Sheet row` wrote 13 blank columns.** After the reorder its `$json` was the Telegram send response, not the `/process` output. Worse, `$json.report.chantier` throws on undefined, and with `continueErrorOutput` set that meant *every* report would silently divert into the retry queue. → Rebound to `$('Process output').item.json.*`.
7. **SEV-1 — dedup gate accomplished nothing.** `Restore message` returned `$('Correlate').all()` — all items, ignoring the `Fresh?` filter — so duplicates were reprocessed anyway. It also dropped `pairedItem`, breaking `$('X').item` for any batch of 2+ simultaneous messages. → `Fresh?` and `Restore message` swapped; restore is now index-aligned with explicit `pairedItem`.
8. **SEV-1 — 5 log nodes recorded `correlation_id: null`**, defeating the whole correlation feature. → Repointed at `$('Restore message').item.json.*`.
9. **SEV-2 — cron would have failed every drain:** placeholder spreadsheet ID, OAuth2 credential where the project uses a service account, and 4 missing columns. → All corrected from the primary node.
10. **SEV-2 — poison-pill loop.** `attempts` was incremented but never read, so a malformed payload retried every 5 min forever *and*, being oldest, permanently occupied the head of the queue window, starving newer reports. → `pending_writes()` now filters `attempts < 10`.

### Frontend

11. **HIGH — request storm.** `search` was in the fetch dependency array, so every keystroke fired a request *and* reset the 5 s poll timer — fast typing could starve the poll entirely. → 300 ms debounce.
12. **MEDIUM — stale-response race.** A slow response could overwrite fresher data. → Request-id guard.
13. **MEDIUM — i18n key leak.** An unknown stage from the API would render the literal string `logs.stage.foo`. → Falls back to the raw stage name.

Reviewers confirmed **no** regression from the Tailwind token bridge and no problems with the Badge variant union or interval cleanup.
