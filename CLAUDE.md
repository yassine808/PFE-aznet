# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

PFE (end-of-studies project, deadline Aug 31 2026) at aznet.ma: voice notes in Moroccan Darija from cabling technicians (via Telegram) → STT → LLM extraction → professional French summary → Google Sheets → manager notifications. **PLAN.md is the source of truth** for architecture decisions, sprint timeline, and locked choices — read it before proposing design changes. Spec: `docs/cahier-des-charges.md`.

Zero-budget constraint: free tiers only (Groq, Gemini AI Studio, HF Inference, Telegram Bot API, Gmail SMTP, Vercel).

**Reception channels:** **both Telegram Bot API and WhatsApp Cloud API are live** (one workflow, imported from `n8n/aznet-complete.json` — **reception + error handler** since 2026-07-29: the maintenance and daily-report bands moved into the API's own scheduler, `api/app/jobs.py`, so the dashboard can show what ran and re-run it. The error band stayed in n8n because it catches n8n's *own* workflow failures, which the API cannot see — it needs one manual step after import: **Settings → Error Workflow → this same workflow**, otherwise the Error Trigger never fires; brought up E2E 2026-07-23).

**WhatsApp will not quote a voice note** (settled 2026-08-15, do not re-investigate): a reply carrying `context.message_id` for an audio message is accepted by the Cloud API and silently rendered without the quoted bubble, while the identical call for a text message quotes correctly — proven with two direct `graph.facebook.com` calls, no n8n involved. Nothing in the workflow can change it; the ⏳/✅ reactions are what marks a voice note, and they attach to it correctly. Do not rewire the reply nodes' `chat_id`/`message_id` off `$('Filtrer accès')` chasing this — it was tried three ways and all three sent the correct raw id.

**Channel asymmetry — remember this when debugging:** Telegram *polls* (`getUpdates`, outbound, needs no tunnel); WhatsApp is *webhook-driven* and needs a public HTTPS URL. So "Telegram errors but WhatsApp is silent" means two different faults: an error reply proves the message reached the pipeline, silence means it never arrived. The public URL is a **Tailscale Funnel** (`https://<TAILSCALE_HOSTNAME>` → `127.0.0.1:5678`) — a stable hostname, so Meta is configured once and survives reboots. Telegram first (no Meta friction); WhatsApp needed a System User token (no expiry), a published app, a WABA `subscribed_apps` call, a manual GET-echo webhook (n8n's WhatsApp Trigger fails Meta's verification challenge), and media download via a plain HTTP node (native download op returns Bad request). Design is channel-agnostic — both feed one `/process` and one Sheet; the reply returns on the originating channel. Full walkthrough: `docs/setup-guide.md`.

**When WhatsApp goes silent, read the n8n execution history, not the log** (2026-08-15, learned the hard way). n8n logs *unknown* webhooks loudly (`Received request for unknown webhook`) and *successful* ones silently, so those 404 lines are usually stale noise from an old path or a manual probe — treating them as live traffic led to renaming a webhook path that was already correct, which broke a working pipeline. The executions list is the only honest record: `GET /api/v1/executions?limit=100` then `?includeData=true` per id. Read it by shape — a real inbound message runs **~26 nodes**, while Meta's status callbacks (`sent`/`delivered`) and its webhook **Test** button (a payload with an *empty* `statuses` array) run **2** and are correctly dropped at `Extract WA msgs` with 0 items. So a green Test button proves only that the URL is reachable; it says nothing about whether real messages are being delivered. Two settings also live on different objects and drift apart independently: the `messages` **subscription** is on the WABA, the **callback URL** is on the app — Subscribed can stay green while the URL is wrong or was never saved.

## Commands

All Python work happens in `api/` with its venv (Python 3.11, matching the API image and CI — no need for `Optional[X]`, `X | None` is fine):

```bash
cd api
.venv/Scripts/python.exe -m pytest              # run all tests (340, no API keys and no database needed; ~5 min)
.venv/Scripts/python.exe -m pytest tests/test_process_endpoint.py -k test_voice_mode   # single test
.venv/Scripts/python.exe -m uvicorn app.main:app --reload   # dev server on :8000
```

**Four deploy traps — a change can look applied and not be running:**
1. The API is a **built image** (`build: ./api`, source baked in). `docker compose restart api` re-runs the *old* code; use `docker compose up -d --build api`. Verify with `docker exec pfe-api grep -c <new-symbol> /app/app/main.py`.
2. n8n keeps its **own copy** of the workflow in its volume. Editing `n8n/aznet-complete.json` changes nothing until it is re-imported (UI) or pushed (`PUT /api/v1/workflows/{id}` with `X-N8N-API-KEY`). Before pushing, diff live-vs-file: n8n strips its own defaults (`resource`, `httpMethod`, `outputPropertyName`) and adds `"version": 1` to IF conditions, so most differences are noise — but real UI edits hide in the same list. The public API also **rejects `settings` keys it does not accept** (`binaryMode`, `availableInMCP` → 400) and silently keeps whatever it already had, so re-check **Error Workflow** after every push. `push_and_archive.py` refuses a node-set mismatch by design; a *reviewed* structural change (node added/removed/renamed, e.g. the 2026-08-09 `/journal` rewire) pushes with `--allow-node-diff`.
3. The **Dashboard is a built image too** (`build: ./Dashboard`, 2026-08-15). Nothing about `up -d --build api` touches it, so a frontend change needs `docker compose up -d --build web`. This one fails *asymmetrically* and that is what makes it nasty: removing a feature from the API without rebuilding `web` leaves a button that looks alive and 404s — which is exactly what happened when `POST /generate-image` was deleted and the served bundle kept calling it for an hour. **Removing a feature: rebuild `web` first, `api` last. Adding one: `api` first, `web` last.** Verify with `docker exec pfe-web sh -c "grep -rl '<dead-symbol>' /usr/share/nginx/html/assets/"` — empty is clean.
4. A **`.env` edit does not reach a running container** (2026-08-15). `docker compose restart n8n` reuses the existing container with its baked-in environment; only `docker compose up -d n8n` recreates it with the new values. This cost an hour: `WHATSAPP_VERIFY_TOKEN` had been added to `.env` but was still an empty string inside n8n, so the verify branch answered `forbidden` to every challenge — and Meta refuses to save a callback URL whose verification fails, which silently blocks reconfiguring the webhook. Check without printing the secret: `docker exec pfe-n8n sh -c 'echo ${#WHATSAPP_VERIFY_TOKEN}'`.

Whole stack: `docker compose up -d` at repo root → **five services**: `postgres`, `n8n`, `api`, `stt-local` (GPU sidecar) and `web` (nginx, the only published port). They are `restart: unless-stopped`, so the pipeline comes back on its own after a reboot.

**`stt-local` is the local Darija engine, containerised** (`benchmark/Dockerfile`, built on `pytorch/…-cuda12.4-runtime`). Two things about it are load-bearing. The **weights are not in the image and not in git** — 5.8 GB, largest shard 4.7 GB, over GitHub's 2 GB Git-LFS per-file ceiling — so `benchmark/models/` is bind-mounted read-only and `download_models.py` is the versioned recipe. And the model **loads on the first `/transcribe`, not at startup** (`stt_server._ensure_loaded`, lock-guarded so two simultaneous notes cannot both start a 4 GB load and OOM an 8 GB card): the engine answers only when Gemini fails, and an eager load pinned half the card around the clock. The first caller after a container start pays ~235 s inside its own request, which is why `local_darija._http()` allows 300 s. `/health` reports `idle` (nothing asked yet) / `loading` / `ok` / `error`. The GPU block needs a working `--gpus all`; without it the container starts fine and silently runs on CPU at 60-180 s per note, so a missing GPU looks like slowness, not an error. `STT_LOCAL_URL` is **hardcoded** in compose to `http://stt-local:8100` rather than interpolated, because `.env` holds `host.docker.internal` for the host-run uvicorn flow — same reason `DATABASE_URL` is hardcoded there. The API image is built from `api/Dockerfile`; compose overrides two env values for it — `DATABASE_URL` (host `postgres`, not `localhost`) and `GOOGLE_SERVICE_ACCOUNT_JSON` (absolute, because `sheets.py` anchors relative paths to `__file__.parents[2]`, which is `/` in the image). For API work, run `uvicorn --reload` on the host instead and set `API_BASE_URL=http://host.docker.internal:8000` so n8n reaches it. See `n8n/README.md` §7b. Telegram reception variants (polling for local dev, webhook for pilot) and smoke test: `n8n/README.md`.

Tests must pass without any API keys — external SDKs are lazy-imported inside functions and mocked at boundaries in tests. Keep it that way.

## Architecture

Hybrid: **n8n** is the glue (Telegram + WhatsApp reception → media download → HTTP call → Sheets append → notifications); **`api/`** is the custom AI microservice n8n calls. Metadata (date, technicien, canal, lien_audio) is added by n8n, not the API.

Endpoints in `api/app/main.py`: `POST /process` (core: audio, image or text → structured JSON), `POST /daily-report` (`app/daily_report.py`: today's Sheet rows → French manager email), the dashboard read/write pair `GET /reports` + `PATCH /reports/{row}` (`app/sheets.py`), `GET /health` (status + `uptime_seconds` + loaded chains and prompt sizes), `GET|PUT /settings` + `POST /notify/test`, `GET|POST|DELETE /technicians` + `/technicians/lookup` + `POST /persons` + `PATCH /persons/{id}/manager` + `DELETE /persons/{id}` (the org chart, director-only writes), `POST /persons/{id}/profile` + `POST /profiles/refresh` (technician profiles), the auth set `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`, `GET|POST|DELETE /users`, `GET /history`, `POST /page-visit` (`app/auth.py`), `POST|GET /service-samples` (uptime history), `POST|GET /exchanges` (messages that never became Sheet rows, plus the bot's reply — the inbox thread's archive), and the observability set `POST|GET|DELETE /logs`, `POST /logs/claim`, `POST|GET /sheet-queue` + `PATCH /sheet-queue/{id}` (`app/logs.py`, Postgres), the scheduler pair `GET /jobs` + `POST /jobs/{name}/run` (`app/jobs.py`), and `GET /in-flight` (messages that logged `received` with no terminal row — the inbox's ⏳, derived from `pipeline_logs` rather than stored).

**The chat commands are gone** (2026-08-15). `/rapport`, `/modify` and `/supprimer` were a second, text-parsed way into data the dashboard already edits; with them went the four n8n command nodes and their six reply nodes, `GET /rapport`, `POST /modify-command`, `POST /messages/link`, `logs.message_row` and `logs.latest_manager_report`. Telegram now ignores any message starting with a slash. `POST /reply` gained an optional `identity_id` in the same pass, so the inbox composer answers on one chosen channel instead of broadcasting to every identity a technician owns.

**Everything is gated** (`app/auth.py`). Two ways through: a session cookie for humans, `X-API-Key` for n8n — it calls the API on every message and has no browser. `require_user` accepts either; `require_human` rejects the machine (settings, report edits, accounts); `require_director` narrows further. The gate is on the API rather than the login form because the dashboard is a static bundle — a login screen alone would be bypassable from devtools. Sessions are opaque tokens in Postgres, not JWTs, so deleting the row logs that browser out on its next request. `INTERNAL_API_KEY` unset means machine access is **disabled**, never "everyone is a machine". Publish-readiness (2026-07-30): `cors_origins` defaults to the two Vite dev origins, never `*` (main.py comment explains why a wildcard + `allow_credentials` cannot coexist anyway), and `/auth/login` throttles at 8 failures / 5 min per client address — the address is resolved through `trusted_proxy_hops` (1 = nginx alone, 2 = Tailscale Funnel in front of nginx), so a wrong value either lets a script rotate the header or locks every visitor onto one key.

`/process` accepts **exactly one** of `audio`, `image` or `text` — anything else is a 422. Routing by input type happens in n8n (`Media or text?` then `Audio or image?`), never inside the API:

- **STT providers** (`api/app/providers/`): Strategy pattern. `TranscriptionProvider` ABC + `@register("name")` decorator populating a registry; adapters imported at the bottom of `providers/__init__.py` to trigger registration. Three engines: `groq` (Whisper large-v3 by API), `gemini` (multimodal), `local` (HTTP client for the GPU sidecar). `hf-darija` is **gone** — it was pinned to a checkpoint that does not exist, and an unset `HF_TOKEN` made it fail at the token check before it could reach the 404, so it never ran once.

  **The benchmark ran** (2026-08-07/08, `benchmark/STT-BENCHMARK-STATUS.md`): 13 engines, 3 by API and 12 locally on the 3070, over 11 real clips. `config.stt_chain` is therefore `gemini,local,groq` **by evidence** — ordered by accuracy judged by a native Darija speaker against the audio, not by latency. Do not "fix" the order to put the fastest engine first; groq is last on purpose, as the always-available floor. Note WER/CER were deliberately **not** computed (`references.csv` is header-only): the judging criterion is preservation of digits and French technical loanwords, because that is all the journal consumes.
- **Prompts** (`api/app/prompts/`, loaded by `app/prompt_loader.py`): versioned Markdown, not Python literals — a prompt change is a content change and must be visible in review. `00-soul.md` is prepended to every model-facing prompt (identity, never-invent, absence != zero). Read once and `@lru_cache`d, so **restart the API to pick up an edit**; a prompt that can change between two requests makes a bad extraction impossible to reproduce. `stt-vocabulary.md` is the exception and gets **no soul**: Whisper reads its `prompt` as the transcript preceding the clip, not as instructions, so the soul would be echoed into the transcript.
- **Extraction** (`api/app/extraction.py`): ordered `provider:model` fallback chains, one per input shape (`extraction_text_chain`, `extraction_image_chain`, plus `profile_chain` in `config.py`). The chain is tried left to right and returns which model answered; all of them failing raises a combined `ExtractionError` — never silent fallbacks, never invented data (prompt enforces null for absent fields). Rank models with `benchmark/run_model_benchmark.py`, and note that **being in `GET /models` does not mean a model is callable**: the 2026-07-27 run found `gemini-2.5-flash` 404ing and `gemini-3.5-flash` 503ing on every call. The text chain alternates vendors on purpose (Gemini and Groq meter free tiers separately); the image chain is Google-only because the free Groq catalogue has no vision model — reconfirmed 2026-08-15 by enumerating the live catalogue (15 models, none multimodal) and by Llama 4 Scout/Maverick answering 404. **SDK clients are `@lru_cache(maxsize=1)`d** (`_gemini_client`, `_groq_client`), the same rule the three STT providers follow: extraction runs on *every* `/process` call, and building a client per call threw away its keep-alive pool and paid a TLS handshake per report. Consequence for tests: a cached client outlives a monkeypatched `sys.modules["groq"]`, so any fixture that fakes the SDK must call `extraction._groq_client.cache_clear()` on the way in **and** out — `tests/test_extraction_profile.py` is the worked example.
- **Image path**: the vision model reads the photo and fills the schema in one call — there is no intermediate transcription. `rapport_complet` gets the model's own summary prefixed `[photo] ` so it is never mistaken for a quote, and the row is always `flag_review=true`.
- **Error contract**: unknown provider / bad input → 422; engine failure (`TranscriptionError`, `ExtractionError`) → 502 so n8n can catch and flag the row; transcription under 10 chars → `short_transcription` warning, not an error.
- **A clean extraction is not a report** (`schemas.ExtractedReport.has_data`): "salam" extracts perfectly — every data field `null` plus a polite `resume` — and a 200 is indistinguishable from a real report downstream, so the pipeline used to answer "✅ Rapport enregistré" and append a row of blanks. `has_data()` deliberately ignores `resume` (the model always writes one, so it is the one field that cannot tell the two apart); when it is false `/process` adds a `no_report_content` warning, and n8n's `Rapport exploitable ?` IF node skips the Sheet append. That gate sits **after** the reply node, never before — see reply-first ordering below.
- **Profiles — the fifth model** (`api/app/memory.py`): one short French paragraph per technician, written at **03:00** by the API scheduler (`jobs.refresh_profiles`) from their own past reports in the Sheet, stored in `persons.profile`, and injected into the extraction prompt as labelled context. There is deliberately **no table of remembered facts** — the Sheet is already the permanent record, and a second store derived from it would be a cache with no hot path to justify it. It never runs on the reply path: a technician waiting for their summary must not also wait for us to tidy a profile. The prompt bans numbers outright, and `extraction._profile_block` frames the text as informational and forbidden as a source of values — otherwise "intervient surtout sur Sidi Maarouf" is one plausible step from filling `chantier` on a message that never named a site.
- **Observability** (`api/app/logs.py`): PostgreSQL (compose service `postgres`) holding `pipeline_logs`, `processed_messages` (WhatsApp idempotency), `failed_writes` (Sheet retry queue), `exchanges` (the inbox thread's archive — messages whose extraction had `no_report_content` and never became Sheet rows, stored with the bot's reply, pruned on `CHAT_RETENTION_DAYS`), `persons` + `technicians` (see below), `sessions` + `user_actions` + `page_visits` (audit trail), `service_samples` (uptime history) and `app_settings`.
- **One person, many channels — and one table** (2026-08-01): `persons` is the human (name, role, `manager_id`, profile **and credentials**); `technicians` is their channel identities (`channel`, `external_id`, `active`), several per person. The separate `users` table was folded in and dropped: it argued from lifecycle ("a technician never logs in"), which is an argument about *credentials*, not identity — and two tables for one human made a chef who also sends voice notes two unrelated rows, i.e. two boxes on the org chart. **`password_hash IS NOT NULL` is now the whole of "this row is an account"**, so `login()` guards on it explicitly (`verify_password(pw, None)` raises `AttributeError`, which its except clause misses → a 500 that confirms the address exists), `list_users` filters on it, and `list_persons` names its columns instead of `SELECT *` so the hash cannot ride out to the browser. `delete_user` clears the credentials rather than deleting the row — a DELETE would cascade away the person, their channels and their profile. `manager_id` is the org chart and only ever points a tech at a chef: `Dashboard/src/pages/equipe.tsx` draws **three fixed bands keyed on `role`**, never recursion, which is why no cycle guard is needed (`logs.set_manager` refuses only self-parenting). Migration is `_MIGRATE_ACCOUNTS`, guarded and re-runnable; it preserves account ids because the three audit FKs point at them. Tests: `api/tests/test_account_fold.py`. That split is what lets a profile follow the colleague rather than the phone number. `find_technician` filters on `active` so the dashboard's toggle actually revokes access, and both the migration and `upsert_technician` match a person **by name alone** — keying on `(name, role)` split one human in two on live data, because their WhatsApp row said `directeur` and their Telegram row said `tech`. The migration runs on every startup and is wrapped in `DO $$ ... IF EXISTS $$`: it reads `technicians.name`, a column it drops itself, and Postgres plans a whole statement before executing it. n8n POSTs one row per stage; the API logs its own errors with the same `correlation_id`, so both processes join into one timeline in the dashboard's **Logs n8n** panel. Deliberately not the Sheet — a Sheets-backed log goes blind during a Sheets outage. `psycopg2` is lazy-imported and pooled; if `DATABASE_URL` is unset the API prints `[logs] DISABLED` and keeps serving.
- **Reply-first ordering**: in `n8n/aznet-complete.json` the reply to the technician happens *before* the `/journal` call. A failed write parks in `failed_writes` and is drained every 5 minutes by `jobs.drain_sheet_queue` through `journal.file_report` (the same path as the live flow) and only resolves the row once Google accepted it; it never costs the technician their summary. Do not reorder these nodes back.
- **Scheduled jobs** (`api/app/jobs.py`): one daemon thread, a 30 s tick, **six** jobs — Sheet-queue drain (5 min), log/sample retention (03:00), profile rebuild (03:00), reminders, daily report e-mail (`daily_time`, Mon–Sat) and weekly report e-mail (`weekly_day`/`weekly_time`, 0 = Monday to match `datetime.weekday()` and the dashboard's picker). Each carries its own budget in `_TIMEOUT_SECONDS`, sized on real cost: 600 s for the report jobs, which run a Sheet read, SMTP and one LLM call *per chef* (the 180 s of the single-digest era would kill the job, and every chef's stored report with it, as soon as the org chart has a few chefs). A run records **exactly one** outcome: the worker and the timeout path contend for an atomic claim (`_make_claim`), because `worker.is_alive()` and the worker's own check are unsynchronised and a job finishing in that window used to log both a success and a timeout for the same run. The weekly job reuses `daily_report.generate_daily_report` with a date-range label rather than a second prompt — the dashboard's weekly panel has always called it that way. They used to be n8n cron bands; they live here because a cron node cannot show an operator what it produced or let them force a re-run, and the dashboard's **Automation** page does both. A job never raises into the loop — failures are recorded as results, since a thread that dies at 03:00 takes the other three with it and nobody notices until the Sheet is empty. The scheduler only starts when Postgres is reachable; times are read from `app_settings` on every check so an edited hour takes effect without a restart.
- **Mail** (`api/app/mailer.py`): one SMTP path shared by `POST /notify/test` and the daily-report job.
- **Schemas** (`api/app/schemas.py`): `ExtractedReport` is the data contract with n8n and the Sheet — field changes ripple to the extraction prompts, the Sheet columns, and n8n mappings. Rebuilt 2026-08-05 from the director's real tracking file (`Tableau de Suivi projet`): typed quantity fields per journal column (`cables_prepares_m` / `cables_installes_m` / `goulotte_m` / three separate prise counters — bureau, panneau, testée — / `fibre_m` / `interconnexions` / `connexions_optiques_brins`), enum-validated multi-valued location (`etages` RDC/E1..E4, `ailes`, `locaux_techniques` RG/SR1..SR10), stock, `remarques`. An unrecognized location **raises** rather than being dropped, so the extraction chain retries instead of writing an invented floor. **`chantier_mentionne` IS a model field since 2026-08-15** — the technician names their site and that wins; the older rule ("routing comes from the org chart") was inverted because the org chart is only correct while a manager maintains it, and managers do not open the dashboard. It is free text, extracted verbatim and never guessed: the pipeline matches it against the `chantiers` table. `has_data` counts remarques, location, stock and the 25 article fields — but deliberately **not** `chantier_mentionne`, because naming a site is addressing, not work done, and counting it would make "je suis à la DGH" answer "Rapport enregistré" and open a row of blanks. A day with no metres but a blocker ("arrêtés 1h30 sur instruction", "bureaux fermés") **is** the report the director most needs.
- **The bordereau articles** (`ARTICLE_FIELDS`, 25 fields added 2026-08-15): the union of the three real bordereaux (DGH, Extralait, ACAPS), collapsed so one physical thing is one field — DGH's "Câble CAT.6A", Extralait's "Câble informatique Catégorie 6 IPS" and ACAPS's "Cable UTP" are all `cables_installes_m`, which already existed. `journal.ARTICLE_COLUMNS` folds into `NUMERIC_COLUMNS`, so they inherit merge-by-addition, the zero-vs-null rule and the Sheet header from one dict update rather than 25 code paths. The invariant that keeps it correct, and is tested: **no two articles on one site may share a `champ`**, or a single day's work is counted into two contract lines at once. The Rapports tab is now **61 columns**; four of them keep pre-2026-08-05 names (`goulottes_m`, `cables_m`, `bureaux_termines`, `panneaux_raccordes`) because renaming a column orphans every historical row in it — `RAPPORTS_COLUMNS` is where the two vocabularies meet, and anything reading Sheet rows (not schema objects) must use the header names.
- **The journal** (`api/app/journal.py`, `api/tests/test_journal.py`): one row per **(date, technicien)** in that chantier's own tab, mirroring the director's file. Two rules make it correct. **Accumulation** — a second message the same day merges into the existing row (numbers add, locations union, prose appends, stock replaces); a second row would double-count JH and break the totals line, the one number he reads. Chef-only columns (EQUIPE, heures, JH, ordre du jour, taux de réalisation) are never touched by a merge — the dashboard owns them. **Stock reconciliation** — baseline is last known minus installed, a reported figure always wins and becomes the new baseline, and a mismatch emits a `stock_ecart` warning with the delta instead of silently picking a number (a delivery and a loss look identical to arithmetic). Dates are normalized through `_norm_date` because the same day arrives as ISO, as `05/08/2026` and as the serial `46174`; unparseable → appends (visible) rather than merges into the wrong row (not).
- **The Sheet write moved from n8n into the API** (2026-08-05, `POST /journal`): merging into an existing row and reconciling stock need a read-modify-write of the tab, which an IF node cannot do. **Reply-first ordering is unchanged** — n8n still answers the technician, *then* calls `/journal`; a Sheets failure returns 502 *and* parks the row in `failed_writes`. `jobs.drain_sheet_queue` now files through `journal.file_report` too, or a retried row would become the duplicate the live path avoided; a payload the schema cannot parse is resolved as failed rather than blocking the batch behind it forever. **The Rapports mirror** (2026-08-09): `file_report` also appends a flat row to the Rapports tab (`_mirror_rapports`, mapping `RAPPORTS_COLUMNS`: goulotte_m→goulottes_m, cables_installes_m→cables_m, prises_connectees→bureaux_termines, panneaux_prises_brassees→panneaux_raccordes, remarques→observations), so the dashboard's Rapports feed still exists now that n8n writes no Sheet at all — that mapping used to live in untestable n8n expressions, which is why it moved into Python. The mirror is best-effort: a failure logs `sheet`/`error` and never costs the journal row. Row links (`logs.link_message_row`) record the **Rapports mirror row only** since the chat commands were removed (2026-08-15): `GET /audio/row/{rapports_row}` resolves a message's archived voice note through it, which is why it survived while `sheet_row`/`sheet_tab` were dropped as write-only. The live workflow was rewired 2026-08-09: the googleSheets append plus `POST /messages/link`, `Queue failed write`, `Log sheet OK`, `Log sheet failed` are gone; `Rapport exploitable ?` now calls `POST /journal` with **no retry** (the API self-parks; a retry would double-park), and its error branch is the renamed `Log journal failed`. Since 2026-08-15 the false branch is no longer silent: `Record exchange` (`POST /exchanges`) archives the message and the bot's reply in the `exchanges` table, so the dashboard's inbox thread shows the conversation even when nothing was filed — the reply expression is duplicated there because n8n has no way to read its own earlier output back; both branches keep the same technician/date/heure/correlation_id the journal row carries. Pushed with `--push --allow-node-diff`.
- **Chantiers and the bordereau** (`chantiers`, `articles` in Postgres, seeded from the real file): a site owns a journal tab and a contract quantity list. Routing is **the site the technician says** (2026-08-15), then the site on their own most recent row ("sticky", no expiry, and the summary says `(repris du dernier rapport)` so an inherited site is visible on the first message), then the chef's `persons.chantier_id` inherited via `manager_id`, then `Non affecté`. Sticky above the org chart reads backwards until you know why: a stale assignment ahead of a live signal silently misfiles a crew that moved. The chantier is snapshotted onto the row so reassignment never rewrites history. **`journal.resolve_site` must never trust a spoken name as a tab name** — that was `resolve_tab`'s old first branch (`if chantier: return chantier, chantier, []`), safe only because nothing reached it; the moment the voice fills it, "la DGH", "d.g.h" and "DGH" become three tabs, three split bordereaux and a totals line scattered across them. Names are normalized (accents, case, punctuation, spacing, leading article) and matched against the table, deliberately **without** fuzzy matching — `ACAPS` and `ACAPS 2` stay two sites, because collapsing two real ones is a silent wrong row while failing to match only creates a visible unverified one. A genuine no-match creates the chantier marked `verifie = false` and flags the row. `find_technician` returns it in the call n8n already makes. Unrouted senders land in a `Non affecté` tab with a warning — visible and fixable, unlike a dropped row or a guessed site. `GET /chantiers/{id}/bordereau` computes `qte_installee` from the journal on every call and stores it **nowhere**: the journal is the only place a quantity is entered, so a stored total could only drift. An article with no `champ` (a switch, an onduleur) returns `null`, meaning "not tracked here", never "none installed".

Config is env-driven via pydantic-settings (`api/app/config.py`, reads `.env`); keys are optional at startup and checked at call time (fail loudly with a clear message).

## Conventions

- Conventional commits (`feat(api): ...`)
- French domain vocabulary in schemas/prompts (chantier, goulottes_m, resume) — it matches the cahier des charges and the Sheet; don't anglicize
- Dashboard lives in **`Dashboard/`** (`web/` was deleted and rebuilt from scratch 2026-07-26 — do not resurrect it). Vite + React 19 + **Tailwind v4**, so there is **no `tailwind.config.js`**: the whole token layer is CSS-first in `src/index.css` (`@theme` holds the raw OKLCH ramp, `@theme inline` maps semantic names onto CSS vars that `:root`/`.dark` redefine). No shadcn, no Recharts — charts are hand-built SVG/CSS, animation is `motion/react`, icons are Phosphor (**the `*Icon` suffix is required**; bare names are deprecated). `@/` is aliased to `src` in **both** `vite.config.ts` and `tsconfig.json`. Design intent and its named rules: `DESIGN.md`, `PRODUCT.md`.
- **All UI copy lives in `Dashboard/src/locales/{fr,en,ar}.json`** (fr is the reference/fallback, **422 keys** each) — never hardcode strings in components; add the key to all three files. Arabic drives RTL, so use logical properties (`ms-`/`me-`/`start`/`end`), never `ml-`/`mr-`. `scripts/check_locales.py` enforces fr/en/ar **parity but never usage**, which is how 77 keys from the deleted pipeline/workflow/team/access pages survived until 2026-08-11. Before deleting a key, check it is not reachable through a dynamic `` t(`prefix.${…}`) `` — those templates are why the `team.` family is still present.
- Dashboard data flow: `useApi(key, fetcher, pollMs)` in `src/lib/api.ts` reads through a **module-level cache**, so navigating away and back repaints instantly and revalidates in the background — without it every panel reloads from a blank state. Ops polling and the uptime sampler live in `OpsProvider` *above* the router (`src/lib/ops-context.tsx`); moving them into a page stops them on navigation and leaves fake gaps in the uptime history. Perpetual motion (status pulse, breathing glow) is CSS keyframes, not React state, so re-renders cannot restart it. Metrics are computed client-side from `/reports`; only uptime comes from `/health` + `/service-samples`.
- Dashboard pages (`Dashboard/src/pages/`): overview, inbox, reports, daily, weekly, automation, **logs** (live pipeline tail, red errors / green rest), **equipe** — the org chart, which replaced the old `team` and `access` pages when `users` folded into `persons` (both hash routes still alias to it in `lib/router.ts`). Three bands (directeur → chefs → techs), connectors are CSS pseudo-elements in `index.css` (`.org-branch`/`.org-node`/`.org-stem`) not an SVG overlay, so RTL and resize need no re-measure. Reassignment is **native HTML5 drag-and-drop** (no dnd dependency) — it fires on neither touch nor keyboard, so the `<select>` in the detail panel is the real path for both, not a fallback. Only the hovered drop target takes the accent ring (DESIGN.md's Ten Percent Rule). The detail panel branches on role: an account gets the activity blocks (`components/team-activity.tsx`, lifted out of the deleted `pages/team.tsx`), a technician gets channels + profile + access, because a tech never signs in and would otherwise stare at three permanently empty panels. Login is `pages/login.tsx` behind `lib/auth.tsx`; the page-timer lives **above the router** in `App.tsx` — inside a page it would unmount before it could report — and flushes with `sendBeacon` on `pagehide`.
- n8n's API is reached through the Vite dev proxy (`/n8n`), which attaches `X-N8N-API-KEY` server-side — the key lives in `Dashboard/.env` **without** a `VITE_` prefix so it never reaches client JS. That also means n8n panels only work under `npm run dev`. Since 2026-07-30 the API has its own `N8N_API_KEY`/`N8N_URL` (`config.py`, proxied in `main.py`), so the container path works too.
- The Vite dev proxy targets **`http://127.0.0.1:8080`** (the compose nginx), not the API directly: the `api` service publishes no host port on purpose, so `:8000` refuses and every dev call 502s. nginx already maps `/api/ → api:8000/`, so there is **no `rewrite`** — stripping the prefix lands on the SPA's `try_files` and returns `index.html` instead of JSON.
- Client-only settings live in `lib/settings.tsx` (localStorage): refresh interval, density, and the **confidence threshold, which is `directeur`-only** — the gate is a `user?.role` check in `settings-panel.tsx`, not an API rule, because the value never leaves the browser. If it ever moves to `app_settings` it needs a real `require_director`.
- Pyright: IDE may flag false positives if not using `api/.venv`; pytest is ground truth (`api/pyrightconfig.json` points at the venv)
